## Follow-up correction — kernel Repo layout and manifest alignment

- The earlier build script attempted to initialize the kernel Repo client inside the Android source tree. This is not a safe Repo layout: a second Repo client must not be initialized inside the existing Android Repo checkout.
- The kernel source must still land at `kernel/xiaomi/mithorium-4.19/kernel`, as required by `TARGET_KERNEL_SOURCE`.
- The build script is corrected to initialize and sync the kernel manifest in a sibling directory outside the Android source checkout, generate its pinned manifest there, and then move the complete kernel Repo client into the expected source path. On later runs, it moves the existing kernel checkout back to the sibling sync location before updating it.
- The local manifest hardware project path for the LA.UM.8.6.2 display HAL was corrected to include the upstream `/display` suffix.
- Removed the extra `android_device_xiaomi_Mi8937_4_19` helper checkout from the local manifest. Its README says the actual 4.19 product/device files are already in `device/xiaomi/Mi8937`; the 4.19 lunch product is declared in that unified tree's `AndroidProducts.mk`.

Evidence inspected:

## Known Mi-Thorium audio HAL compile issue — patched in build automation

A further source inspection found a likely Android 15 Clang build failure in the selected Mi-Thorium audio HAL branch:

- HAL branch: `mithorium/LA.UM.9.6.4.r2-04300-89xx.QSSI13r2.0`
- Current branch tip observed by the GitHub preflight begins `a3ff9d54`.
- `hal/audio_extn/cirrus_playback.c` and `hal/audio_extn/spkr_protection.c` declare thread functions with unnamed `void*` parameters.
- These definitions rely on a C23 extension and may be rejected when compiled in GNU99 mode with Clang's `-Wc2x-extensions` under `-Werror`.

The project now contains:
- `patches/0001-audio-extn-name-unused-pthread-parameters.patch`
- Build-script logic to apply the patch after Android Repo sync, skip it if already applied, and fail early if it no longer applies cleanly.
- Upstream preflight checks for the exact affected HAL source signatures.
- Static checks that verify the patch file and build-script integration are present.
